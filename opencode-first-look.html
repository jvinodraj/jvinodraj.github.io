My First Look at OpenCode

October 2024 Tooling

Why did I start looking for an alternative?

I've been using GitHub Copilot in VS Code quite extensively. It's convenient right there in the editor, suggesting completions, helping with boilerplate. But very soon, I have the pain of watching my usage meter climb the ladder.

I wanted to keep experimenting with AI, writing more prompts, trying different approaches without constantly watching a usage meter. That's when I started exploring OpenCode.

What caught my attention?

The first thing that stood out: free model access. OpenCode gives you immediate access to multiple models like Nemotron 3 Ultra and Llama 3.1 405B through their hosted inference - no API keys, no credit card, no setup. You can also bring your own keys for other providers if you want.

Then I saw the model list. NVIDIA Nemotron 3 Ultra 550B parameters. A model of that scale, available to experiment with at no cost? That got my attention. Of course, free access depends on the provider and their limits, but having the option to test large-scale models without committing to a paid tier changes how you approach exploration.

It also made me realize: I'd been dependent on a single AI assistant. OpenCode lets me swap models mid-task and use a reasoning-heavy model for architecture decisions, a faster one for quick edits all in the same session.

More prompting without losing context

When working on something complex like an MCP server, an agent workflow, a data pipeline, I don't get it right in one prompt. I ask, refine, test, ask again. I need the conversation history and the project context to carry forward.

OpenCode handles this through persistent sessions. Each session remembers the full conversation, the files you've touched, the context you've built. You can close the terminal, come back tomorrow, run opencode connect --session ses_abc123, and pick up exactly where you left off.

This matters when you're learning. You're not just getting answers but also you're building a thread of reasoning that you can revisit, export, or share.

Three commands I reach for daily

opencode connect - Resume a session

opencode connect --session ses_abc123

Sessions persist - context, file edits, history. Switch machines, continue a multi-day task, no context lost.

opencode model - Switch models on the fly

opencode model --set nvidia/nemotron-3-ultra

Different models for different tasks. No restart. Just switch and keep going.

opencode export - Extract session artifacts

opencode export --session ses_abc123 --format markdown

Export conversation, diffs, or final code changes. Clean handoff to PRs, docs, or team review.

Installation & Access

Install (one-liner)

# macOS / Linux curl -fsSL https://opencode.ai/install.sh | bash # Windows (PowerShell) irm https://opencode.ai/install.ps1 | iex

Verify

opencode version # → opencode 0.x.x

Run in Command Prompt / Terminal

Navigate to any git repository and start:

cd my-project opencode

OpenCode reads the repo, detects the stack, opens an interactive session. Type your task, hit Enter.

Run in VS Code

Two options - pick your flow:

Option A: Integrated Terminal (recommended)

  1. Open project folder in VS Code (File → Open Folder)
  2. Open terminal: Ctrl + ` or Terminal → New Terminal
  3. Run opencode - full session inside VS Code

File edits appear instantly in the editor, git changes show in Source Control, zero context switch.

Option B: VS Code Extension

code --install-extension opencode.opencode

Sidebar with session history, model picker, one-click resume. Still uses the terminal underneath.

First Run Checklist

  • Git repo required - OpenCode needs a .git directory
  • Optional: AGENTS.md - Project instructions for the agent (docs)
  • Optional: .opencode/ - Local config, custom tools, MCP server definitions

Where This Fits My Stack

I build agentic AI systems - MCP servers (Power BI, data observability) for agent workflows, evaluation pipelines. OpenCode doesn't replace those tools. It accelerates the development loop for them.

Faster iteration on prompts, tool definitions, integration logic. Since it speaks MCP natively, I can test my Power BI MCP server end-to-end without leaving the terminal. That's a real workflow win.
